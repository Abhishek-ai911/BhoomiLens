# BHOOMILENS PROJECT HANDOFF

## Project

BhoomiLens

BhoomiLens is a land-record reconciliation and decision-support system for SIH 2026.

It reconciles different records associated with a land parcel, detects conflicts/anomalies using deterministic rules, identifies relevant authority, presents evidence, calculates Clarity and Priority, detects transaction patterns, and supports human officer review.

BhoomiLens is NOT an automatic fraud-decision system.

# CONFLICT DETECTION

Conflict detection must be deterministic.

Relevant conflict areas include:

- ownership mismatch
- mutation mismatch
- tax mismatch
- area mismatch
- boundary anomaly
- land-use mismatch
- court conflict
- freshness
- missing/unavailable information

---

# AUTHORITY

Authority determination must use the Authority Matrix.

Conceptually:

jurisdiction + attribute
→ authority rule
→ relevant authoritative source

Examples:

Rajasthan + cadastral geometry → Survey

Rajasthan + mutation → Revenue

Rajasthan + registered transaction → Registration

Competing legitimate sources can result in contested authority and human review.

---

# EVIDENCE

Evidence should answer:

- What?
- Why?
- Source?
- Record ID?
- Date?
- Value?
- Comparison?
- Authority where applicable?

---

# CLARITY AND PRIORITY

Clarity and Priority are separate concepts.

Clarity:

How internally consistent and complete is the information?

Priority:

How urgently should an officer investigate?

Example from the specification:

P004:
Priority = HIGH
Clarity = 41/100

Do not treat Clarity and Priority as the same thing.

---

# TRANSACTION PATTERNS

Transaction pattern detection must be deterministic PostgreSQL/business logic.

Do NOT use ML or Neo4j.

Required patterns include:

1. Transaction velocity

Example:
3+ transactions within 12 months
→ unusual velocity
→ enhanced review recommended

2. Circular transaction

Example:
A → B → C → A
→ circular pattern
→ enhanced review required

This must NOT automatically be labeled fraud.

3. Recurring entity pattern
